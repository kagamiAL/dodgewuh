# Two-to-three-minute demonstration

Goal: show two people communicating to control one character, physical activity, then role exchange. Describe a prototype for social active play, not a proven health intervention. Reusing existing phones and browser access reduces participation friction; no quantified sustainability or medical claims.

## Setup

Use pinned working release, charged four phones, one primary screen/projector plus second screen, reliable venue network and hotspot backup. Start with room code visible and devices calibrated; keep one clean join flow ready to show briefly. Clear space for modest torso leans and short controlled phone gestures; players retain firm grip and never release the phone. Seated upper-body lean can demonstrate an accessible motion variant without claiming universal accessibility. Turn off auto-lock for the demo with participants' consent, restore afterward.

Alan presents and watches connection status. Richard and Ryan operate Team 1; Morteza and Tysen operate Team 2. These demonstration roles are unrelated to code ownership. Keep roles/teams visible; no one silently drives a character from keyboard.

## Script

| Time | Action and spoken point |
|---|---|
| 0:00–0:25 | Alan: “Four people, two characters. One teammate moves; the other aims and throws.” Show code and four ready phones, browser-only join. |
| 0:25–0:55 | Team 1 Legs physically leans toward ball while Arms holds. Say “move closer; I have it; back out of the zone.” Show that neither can act alone. |
| 0:55–1:25 | Demonstrate aim with phone, short controlled gesture and release outside zone; opposing Legs dodges or accepts a legitimate hit. Show server score on both screens. |
| 1:25–1:55 | Phones swap Arms/Legs. Players recalibrate, tap Ready; next round resets. Explain both teammates experience both forms of control. |
| 1:55–2:25 | Play another short exchange; show second screen agrees. Alan: Python on AWS decides the game; screens render the same state. |
| 2:25–2:50 | Show a previously completed match/winner if live game is not yet finished, label it recorded. Explain active play and communication using devices people already own. |

A first-to-three match need not finish inside the spoken slot. Do not change gameplay rules secretly for demo speed. Full-match evidence comes from rehearsal/recording; live segment demonstrates actual mechanics and mandatory swap.

## Rehearsal and failure response

At H16 record a complete successful deployed match plus a 30-second close-up of physical controls. At H18 pin SHA and capture device/network details. Rehearse twice by H23. Ryan keeps recording locally so loss of venue network does not prevent playback. Alan keeps previous release and rollback instructions.

If phone disconnects, explain and return lobby, reconnect/calibrate/restart once. If more than 20 seconds is lost, switch to the labelled recording and explain the failure honestly. If internet fails, a pretested local HTTPS setup may be used; call it local and retain cloud recording evidence. If no usable phone motion, show recorded real-phone gameplay rather than pretending touch controls satisfy the mechanic. Single-screen fallback is acceptable for presentation continuity but not a passed multi-screen acceptance test.

Final checklist: four phones charged, two screens, domain/cert healthy, known-good release, room created, roles visible, sensors enabled, no-throw zone visible, safe movement area, recording available offline, host knows reset/rematch, and all five presenters know the short script.
